# Binding Generator

The nanobind bindings in this directory are generated by
[litgen](https://github.com/pthom/litgen), supplied by the build environment
rather than vendored into this repository.

## Selecting the litgen checkout

litgen output is **not** stable across versions, so one checkout is pinned per
environment.  `CMakeLists.txt` resolves it in this order:

1. `-DSYMENGINE_LITGEN_DIR=<checkout>/src` on the CMake command line;
2. `$LITGEN_ROOT/src` from the environment (what `.ci/ci-common.sh` exports);
3. `/opt-6/litgen-6085aaa/src`, the checkout staged in the CI image.

Configuration fails with a clear message if the resolved directory is missing.

## Regenerating

```sh
export PYTHONPATH="/opt-6/litgen-6085aaa/src:${PYTHONPATH:-}"   # or your checkout
python generator/generate.py generator/generate.yaml
```

The CMake build also regenerates automatically when `generate.py` or
`generate.yaml` change (see `CMakeLists.txt`).

## Legacy API inventory

`scripts/extract_inventory.py` prints an inventory of the legacy Cython
wrapper's classes and functions.  It is a developer reporting aid for measuring
`nbsymengine_compat` coverage; no build step consumes it, and it does not define
this wrapper's C++ API.

## Policy

Generated litgen output (`symengine_pydef.cpp`, `symengine.pyi`) is **never
tracked in git**.  The `generated/.gitignore` enforces this.

- **Source checkouts** regenerate bindings at build time into the build tree.
- **sdist tarballs** include pre-generated copies in `generated/` so that
  downstream builds do not require litgen.

The hand-written `_core` module scaffold (`src/core_module.cpp`) is tracked
despite including generated code via `#include "symengine_pydef.cpp"`.

## Shared adapter functions (YAML → .inc / .pyi)

`../binding-spec/api.yaml` drives the typed shared renderer in
`../tools/binding_codegen`. It emits `generated/symengine_simple_funcs.inc`
and matching `.pyi` declarations from one model.

To regenerate the `.inc` by hand:

```sh
python3 -m tools.binding_codegen generate --language python \
    --output generated
```

The CMake build regenerates automatically when the spec or renderer changes.
The `.inc` is a build artifact and is never tracked in git (covered by
`generated/.gitignore`).
